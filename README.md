# Рекомендательный сервис постов для социальной сети

REST API-сервис, который формирует персональную ленту постов для пользователя социальной сети. Сервис оценивает вероятность лайка каждого доступного поста и возвращает посты с наибольшими оценками.

## О проекте

Проект объединяет исследование данных, feature engineering и модель градиентного бустинга:

- пользовательские признаки: пол, возраст, страна, город, операционная система, источник привлечения и экспериментальная группа;
- признаки постов: тема, длина текста, количество слов и средняя длина слова;
- текстовые признаки: TF-IDF, снижение размерности с помощью TruncatedSVD и кластеризация текстов методом KMeans;
- временные признаки: час, день недели, выходной день и часть суток;
- история лайков пользователя для исключения уже понравившихся постов.

Модель обучается на временном разделении данных: ранние события используются для обучения, а более поздние — для проверки качества.

## Результаты

На отложенной временной выборке получены следующие значения:

- **ROC-AUC:** `0.7125`;
- **PR-AUC:** `0.1805`.

Доля положительного класса в тестовых событиях составляет около 9,16%, поэтому случайный baseline для PR-AUC равен примерно `0.0916`. Полученный результат почти в два раза выше случайного уровня.

В ноутбуке использовано:

- 163 205 пользователей;
- 7 023 поста;
- 3 500 000 событий просмотра;
- 37 признаков для обучения;
- CatBoostClassifier для предсказания вероятности лайка.

## Архитектура решения

### 1. Подготовка данных и EDA

Из PostgreSQL загружаются данные пользователей, постов и событий просмотров. Выполняется проверка пропусков, распределения целевой переменной и временного диапазона событий.

### 2. Формирование признаков

Для пользователей и постов создаются статические признаки. Из текстов постов формируются TF-IDF-векторы, которые преобразуются методом TruncatedSVD и группируются в 16 текстовых кластеров.

Для каждого события также рассчитываются признаки даты и времени. Затем пользовательские, постовые и временные признаки объединяются в единую обучающую выборку.

### 3. Обучение модели

CatBoostClassifier предсказывает вероятность того, что пользователь поставит лайк посту. Для валидации используется временное разделение, чтобы не использовать события из будущего при обучении.

### 4. Inference и API

При запуске приложение:

1. загружает модель из `model.pkl`;
2. загружает признаки пользователей, постов и историю лайков из PostgreSQL;
3. принимает запрос с `user_id`, временем рекомендации и количеством постов;
4. исключает уже лайкнутые посты;
5. ранжирует оставшиеся посты по вероятности лайка;
6. возвращает top-N рекомендаций.

## API

### `GET /post/recommendations/`

Возвращает персональные рекомендации для пользователя.

Параметры запроса:

| Параметр | Тип | Обязательный | Описание |
|---|---|---:|---|
| `user_id` | integer | да | Идентификатор пользователя |
| `dt` | datetime | да | Дата и время формирования рекомендаций |
| `limit` | integer | нет | Количество рекомендаций, по умолчанию `10` |

Пример запроса:

```bash
curl "http://localhost:8000/post/recommendations/?user_id=200&dt=2021-10-05T12:00:00&limit=5"
```

Пример ответа:

```json
[
  {
    "id": 123,
    "text": "Post text...",
    "topic": "business"
  }
]
```

Для интерактивного просмотра API после запуска откройте Swagger UI: <http://localhost:8000/docs>.

## Структура репозитория

```text
.
├── app.py             # FastAPI-приложение и логика рекомендаций
├── database.py        # Подключение к PostgreSQL
├── schema.py          # Pydantic-модели API
├── Project_ML.ipynb   # EDA, подготовка признаков и обучение модели
├── requirements.txt   # Зависимости проекта
└── .env.example       # Пример переменной подключения к БД
```

Приложение ожидает в базе следующие подготовленные таблицы:

- `rec_user_features` — признаки пользователей;
- `rec_post_features` — признаки постов;
- `rec_user_likes` — история лайков пользователей.

## Локальный запуск

### 1. Клонирование и переход в проект

```bash
git clone https://github.com/your-username/recsys-project.git
cd recsys-project
```

### 2. Создание виртуального окружения

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
```

Проект рассчитан на Python 3.13.

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка подключения к базе данных

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Укажите URL подключения к PostgreSQL:

```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DB_NAME
```

Не добавляйте `.env` и пароли в Git.

### 5. Запуск сервиса

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

После запуска API будет доступен по адресу <http://localhost:8000>, а документация — по адресу <http://localhost:8000/docs>.

## Обработка холодного старта

Если пользователь отсутствует в таблице признаков, сервис не прекращает работу: для него создаётся набор признаков на основе медианных и наиболее часто встречающихся значений по пользователям. Рекомендации при этом формируются по общей модели и признакам постов.
